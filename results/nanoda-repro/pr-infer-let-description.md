Fixes #62.

**Impact.** nanoda no longer evaluates a `let` value that the proof never needs evaluated. On the Lean Kernel Arena test [`perf/let-fold`](https://github.com/leanprover/lean-kernel-arena/blob/237766c685ee5902411f740e406706ba290c8f2c/tests/perf/let-fold.yaml), master (37cb87b) takes 1.43 s and this branch 0.01 s (the official kernel takes 0.04 s on the Arena). On openai/math, `OAI.SquareDifference.source_ordered_contraction` from #62, which overflows the stack on master and with an 8 GiB stack was still running after 34 minutes at 96 GB, now checks: the whole SquareDifference configuration takes 17 s and 0.65 GB at the default stack (4 threads).

**Cause.** `infer_let` substitutes the value into the body before inferring its type. The openai/math lemma starts with `let d := Fintype.card TupleVertex`, so after substitution terms like `2 * d` are closed `Nat` arithmetic, which `try_reduce_nat` evaluates by enumerating a very large `Finset.univ`. Lean's kernel (`type_checker::infer_let`) instead checks the body with `d` as a free variable in the local context, unfolded only when `whnf` needs it, and folds `Nat` literals only in terms without free variables. The same declaration and cause were found independently while developing con-leche, and Joachim Breitner turned them into `perf/let-fold`.

**Change.** After the existing checks of the annotation and the value, `infer_let` makes a fresh local (`mk_unique`) for the bound variable, records its value in `TcCache::let_vals`, infers the body's type with the local, and substitutes the value into the result. `whnf_no_unfolding_aux` unfolds such a local when it is the head of the term. Unique ids keep lets with the same name and type apart in the expression-keyed caches, and `let_vals` lasts as long as the `TcCache`, which is one declaration.

**Soundness and tests.** The checks of the annotation and the value are unchanged, and the only new conversion unfolds a let-bound variable to its value; where it is not unfolded it is an opaque local, which can only lead to a rejection. The new tests in `src/tests/infer_let.rs` use small exports in `test_resources/Let` in which checking each proof needs a let-bound value: one well-typed export, and one ill-typed export each for sibling lets with the same name and type, shadowing lets with the same name and type, two declarations with the same let shape, and a value whose type doesn't match the annotation. Lean's kernel agrees on all five. Two deliberately broken versions of this change (one without the value check, one keying values by name and type) each fail some of them. `cargo test` passes (59 tests). The exports are generated from a small Lean file by `tools/nanoda_let_pr_resources.py` in https://github.com/nealmcb/openai-math-lean-tooling.

**Other openai/math configurations.** On 8199c74, this change together with the `Nat.succ` guard proposed in #61 was run over all 416 openai/math configurations: none got worse, 7 that failed now pass, and total time was 0.93x. The configurations that still overflow on current master are about #61, not `let`.
